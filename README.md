## 📌 Описание проекта (Этап 1: Данные + Первый индекс)

Индивидуальный проект посвящен исследованию тенденций сокращений и найма в технологическом секторе (2025–2026 гг.) и практическому применению алгоритмических структур данных.

- **Источник датасета:** Kaggle (`Tech Layoffs & Hiring Trends 2026`).
- **Размер выборки:** от 1 000 до 100 000+ строк (требование дисциплины выполнено).
- **Ключевые поля:**
  - `record_id` — уникальный идентификатор записи (первичный ключ индексации);
  - `company_name`, `industry`, `country` — категориальные признаки;
  - `layoffs_count`, `workforce_cut_pct` — числовые метрики сокращений;
  - `date` — упорядочиваемый хронологический признак;
  - `company_name → industry` — связь объектов с числовой характеристикой `layoffs_count`.

## ⚙️ Реализованные структуры данных (v0.1)

### 1. Собственная Хеш-Таблица (`MyHashMap`)
- **Разрешение коллизий:** метод цепочек (*Separate Chaining*): `bucket → [(key, value), ...]`.
- **Начальная ёмкость:** `capacity = 8`.
- **Порог загрузки:** `MAX_LOAD_FACTOR = 0.75`.
- **Динамическое расширение:** при `(size + 1) / capacity > 0.75` происходит удвоение `capacity` в 2 раза и полный `rehash` всех существующих пар.
- **Временная сложность:**
  - Поиск в среднем: $O(1)$;
  - Поиск в худшем случае: $O(N)$ (при вырождении цепочек);
  - Память: $O(N + \text{capacity})$.

### 2. Эксперимент: Linear Search vs Hash Lookup
Проведено сравнительное тестирование на 30 равномерно распределенных запросах:
- **Линейный поиск:** полный проход массива $O(N)$ ($\approx 3-5$ мс на 10 000 строк);
- **Индексный поиск по хешу:** $\approx 0.03-0.08$ мс;
- **Ускорение:** более чем в $100\times$ раз.
